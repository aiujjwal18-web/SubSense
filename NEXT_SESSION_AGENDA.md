## 0. Stale reminders not invalidated on renewal-date change or pause — DEC-070 shipped, DONE

**Found live, not in testing:** after the 401/403 fixes finally let `send-reminder-email` deliver its backlog, the user received several reminder emails whose content contradicted the current Subscriptions dashboard state — e.g. Amazon Prime (dashboard: "Renews 29 Aug 2026," far outside any reminder window) still sent "renews today" and "renews in 7 days" emails; Amazon Prime Video (dashboard: **Paused**) still sent all three of its "renews today"/"in 2 days"/"in 7 days" reminders. The multiple-emails-per-subscription pattern itself (7-day/2-day/day-of touchpoints) is correct by design, DEC-039 — the bug was that stale ones from a superseded state never got cancelled.

**Root cause, confirmed by reading the actual trigger code (`17_SubSense_Migration_v2.sql`):** `generate_default_reminders()` inserted fresh reminders for a new `next_renewal_date` but never cancelled the old pending rows from the previous cycle, and no trigger reacted to `lifecycle_status` entering `'paused'` at all — exactly the gap DEC-064's own text flagged and explicitly deferred. Confirmed worse than cosmetic: doc 10's partial unique index on pending reminders means a stale pending row silently blocks the next cycle's reminder of the same type from ever being inserted, not just delivering wrong content once.

**Fixed and drafted the same session, per the user's decision to proceed immediately rather than wait:** recorded as **DEC-070** in doc 08 (bumped to v1.42). Ships `29_SubSense_Reminder_Lifecycle_Patch_v1.0.sql` — a new `reminder_status` value (`skipped_superseded`), `generate_default_reminders()` refactored into a thin wrapper over a new callable helper (`generate_default_reminders_for_subscription()`), and a new trigger (`subscriptions_cancel_stale_reminders`, ordered to fire before the existing generate trigger) that cancels stale pending reminders on a renewal-date change or entering `'paused'`, and regenerates the default set on resuming from `'paused'`.
